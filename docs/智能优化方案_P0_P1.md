# TB Import Tool 智能优化方案（P0 + P1）

## P0-1：语义去重 — 替换 difflib 模糊匹配

### 现状问题

当前去重管道（`sync_engine.py:_find_existing_task`）共 5 层：

| 层级 | 方法 | 局限 |
|------|------|------|
| T1 | 精确搜索 `【禅道{id}】` 标签 | 仅限已同步过的 Bug |
| T1.5 | VLNS/CPAX 编号精确匹配 | 仅限有编号的 Bug |
| **T2** | **`difflib.SequenceMatcher` 字符串相似度** | **同义不同词无法匹配** |
| T3 | 备注/历史 VLNS/CPAX 回退 | 仅限特定标记 |
| T4 | 模块/组件过滤 | 仅缩小范围 |

T2 的核心问题示例：
- "机器无法回充" vs "扫地机不回基站" → 语义相同但字符串相似度仅 ~0.15
- "路径规划异常导致重复清扫" vs "同区域反复清扫" → 语义相同但几乎无共同字符

### 方案设计

#### 架构

```
┌──────────────┐     ┌──────────────────┐     ┌──────────────┐
│  Zentao Bug  │────▶│  Embedding 模型   │────▶│  向量存储     │
│  标题+描述    │     │  (本地/在线)       │     │  (TB任务索引) │
└──────────────┘     └──────────────────┘     └──────┬───────┘
                                                       │
                     ┌──────────────────┐              │
                     │  余弦相似度计算    │◀─────────────┘
                     │  (numpy)          │
                     └────────┬─────────┘
                              │
                     ┌────────▼─────────┐
                     │  去重判定         │
                     │  阈值: 0.85       │
                     └──────────────────┘
```

#### 模型选型

| 方案 | 模型 | 大小 | 延迟 | 中文效果 | 推荐 |
|------|------|------|------|---------|------|
| A. 本地轻量 | `text2vec-base-chinese` | ~400MB | ~5ms/条 | 好 | ✅ 推荐 |
| B. 在线 API | LLM embedding (通义/智谱) | 0 | ~50ms/条 | 极好 | 备选 |
| C. 混合 | 本地初筛 + 在线精排 | ~400MB | 混合 | 极好 | 高精度场景 |

**推荐方案 A**：`text2vec-base-chinese` 无需 GPU、CPU 推理即可、离线可用、中文领域效果优秀。

```python
    def __init__(self, model_name="shibing624/text2vec-base-chinese"):
        from sentence_transformers import SentenceTransformer
        self.model = SentenceTransformer(model_name)
        self._vectors = None      # numpy (N, dim)
        self._task_ids = []       # 对应的 taskId
        self._titles = []         # 对应的标题（调试用）
        self._dim = self.model.get_sentence_embedding_dimension()

    def build_index(self, tasks: list[TeambitionTask]):
        """从 TB 任务列表构建向量索引"""
        texts = [t.get_base_title() for t in tasks]
        self._vectors = self.model.encode(texts, normalize_embeddings=True)
        self._task_ids = [t.taskId for t in tasks]
        self._titles = texts

    def search(self, title: str, threshold: float = 0.85) -> Optional[TeambitionTask]:
        """查找语义相似的已存在任务"""
        query_vec = self.model.encode([title], normalize_embeddings=True)
        scores = numpy.dot(self._vectors, query_vec.T).flatten()
        best_idx = numpy.argmax(scores)
        if scores[best_idx] >= threshold:
            return self._task_ids[best_idx], scores[best_idx]
        return None

        """加载已有索引（增量更新）"""
        ...
```

## P0-2：智能字段自动补全

### 现状问题

当前字段提取全部基于正则表达式：

| 字段 | 提取方式 | 覆盖率 |
|------|---------|--------|
| SN编码 | `ZentaoClient._extract_sn()` — 4种正则 | ~70%（标准格式OK，非标漏掉） |
| 复现概率 | `re.search(r'(?:复现\|重现)(?:概率\|频率)...')` | ~40%（格式多样） |
| 固件版本 | 未实现 | 0% |
| 缺陷产生时间 | 未实现 | 0% |
| 所属模块 | 未实现 | 0% |

正则无法覆盖的典型案例：
- SN: "机器序列号是 abc123" / "sn abc123" / "编码abc123"
- 复现概率: "每次必现" / "大概十次出一次" / "偶尔会"
- 版本: "当前固件 v2.3.5" / "8.1.21版本" / "FW 2.3.5-rc1"

### 方案设计

#### 架构

```
┌────────────────┐     ┌───────────────┐     ┌──────────────┐
│  Bug Steps     │────▶│  正则快速提取  │────▶│  LLM 补全    │
│  (HTML/Text)   │     │  (零延迟)      │     │  (仅正则未命中)│
└────────────────┘     └───────┬───────┘     └──────┬───────┘
                               │                     │
                    ┌──────────▼─────────────────────▼──┐
                    │        字段合并 & 置信度评分         │
                    │  regex(0.9) > llm(0.8) > 默认值    │
                    └───────────────────────────────────┘
```

**核心思路**：正则优先（快、准、免费），LLM 兜底（覆盖非标准格式），两者结果按置信度合并。

#### 实现代码

```python
class SmartFieldExtractor:
    """智能字段提取：正则优先 + LLM 兜底"""

    # 复现概率自然语言 → 标准值映射
    REPRO_MAP = {
        "必现": "必现", "每次": "必现", "100%": "必现", "一定能": "必现",
        "高概率": "高概率", "经常": "高概率", "大概率": "高概率",
        "中概率": "中概率", "有时": "中概率", "偶尔": "中概率", "50%": "中概率",
        "低概率": "低概率", "很少": "低概率", "极少": "低概率",
        "偶现": "偶现", "随机": "偶现", "不确定": "偶现",
    }

    def __init__(self, llm_config: dict = None):
        self.llm_config = llm_config
        self._llm_client = None

    def extract(self, bug: ZentaoBug) -> dict:
        """提取所有字段，返回 {field: (value, confidence)}"""
        text = f"{bug.title}\n{bug.steps or ''}"

        # Phase 1: 正则快速提取（零延迟）
        fields = {}
        fields["sn_code"] = self._regex_sn(text)
        fields["reproduction"] = self._regex_reproduction(text)
        fields["firmware_version"] = self._regex_firmware(text)
        fields["found_time"] = self._regex_time(text)

        # Phase 2: 检查哪些字段未命中
        missing = [k for k, (v, c) in fields.items() if v is None or c < 0.7]

        # Phase 3: LLM 兜底（仅提取未命中的字段）
        if missing and self.llm_config:
            llm_fields = self._llm_extract(bug)
            for key in missing:
                if llm_fields.get(key) and llm_fields[key] != (None, 0):
                    # LLM 结果置信度低于正则，但高于默认
                    fields[key] = llm_fields[key]

        return fields

    def _regex_sn(self, text: str) -> tuple:
        """正则提取 SN（复用现有逻辑）"""
        from src.zentao_client import ZentaoClient
        result = ZentaoClient._extract_sn(text)
        if result and result != "/":
            return (result, 0.9)  # 正则高置信
        return (None, 0.0)

    def _regex_reproduction(self, text: str) -> tuple:
        """正则提取复现概率 + 自然语言映射"""
        import re
        m = re.search(
            r'(?:复现|重现|出现)(?:概率|频率)?[：:\s]*([^\s<]+)', text)
        if m:
            word = m.group(1)
            mapped = self.REPRO_MAP.get(word)
            if mapped:
                return (mapped, 0.85)
        return (None, 0.0)

    def _regex_firmware(self, text: str) -> tuple:
        """正则提取固件版本"""
        import re
        # 匹配 v2.3.5, V2.3.5, 8.1.21, 2.3.5-rc1 等格式
        m = re.search(
            r'(?:固件|版本|FW|firmware)[：:\s]*(?:v)?(\d+\.\d+(?:\.\d+)?(?:-\w+)?)',
            text, re.IGNORECASE)
        if m:
            return (m.group(1), 0.85)
        return (None, 0.0)

    def _regex_time(self, text: str) -> tuple:
        """正则提取缺陷产生时间"""
        import re
        m = re.search(
            r'(?:产生|发生|出现)时间[：:\s]*(\d{4}-\d{2}-\d{2}\s*\d{0,2}:\d{0,2})',
            text)
        if m:
            return (m.group(1).strip(), 0.9)
        return (None, 0.0)

    def _llm_extract(self, bug: ZentaoBug) -> dict:
        """LLM 提取字段"""
        prompt = FIELD_EXTRACTION_PROMPT.format(
            title=bug.title,
            steps=bug.steps or "",
        )
        try:
            result = self._call_llm(prompt)
            data = json.loads(result)
            fields = {}
            if data.get("sn_code"):
                fields["sn_code"] = (data["sn_code"], 0.75)
            if data.get("reproduction_probability"):
                fields["reproduction"] = (data["reproduction_probability"], 0.75)
            if data.get("firmware_version"):
                fields["firmware_version"] = (data["firmware_version"], 0.75)
            if data.get("found_time"):
                fields["found_time"] = (data["found_time"], 0.7)
            return fields
        except Exception as e:
            logger.warning("LLM 字段提取失败: %s", e)
            return {}
```

## P1-1：Bug 关联分析

### 需求场景

测试工程师在实际工作中经常遇到：
- 同一台机器（同 SN）上报了多个不同 Bug，其实是同一个根因
- 某个固件版本集中爆发某类缺陷（批次性问题）
- 重新激活的 Bug 与原始 Bug 缺乏关联记录

### 方案设计

#### 架构

```
┌────────────────┐     ┌──────────────────┐     ┌──────────────┐
│  同步完成的     │────▶│  关联分析引擎     │────▶│  TB 评论/备注 │
│  Bug + TB 任务  │     │  (本地计算)       │     │  标注关联信息  │
└────────────────┘     └──────────────────┘     └──────────────┘
                              │
                    ┌─────────┼──────────┐
                    ▼         ▼          ▼
              ┌─────────┐ ┌────────┐ ┌────────┐
              │ SN 关联  │ │ 版本   │ │ 时间   │
              │ 同机器   │ │ 聚簇   │ │ 聚簇   │
```

#### 三种关联维度

**1. SN 关联 — 同机器多缺陷**

```python
class BugCorrelationAnalyzer:
    """Bug 关联分析引擎"""

    def analyze_sn_correlation(self, bugs: list[ZentaoBug]) -> list[dict]:
        """按 SN 分组，发现同机器多缺陷"""
        from collections import defaultdict
        sn_groups = defaultdict(list)
        for bug in bugs:
            sn = bug.snCode or self._extract_sn_from_steps(bug.steps)
            if sn and sn != "/":
                sn_groups[sn].append(bug)

        correlations = []
        for sn, group in sn_groups.items():
            if len(group) >= 2:  # 同 SN 有 2+ 个 Bug
                correlations.append({
                    "type": "same_sn",
                    "sn": sn,
                    "bug_ids": [b.id for b in group],
                    "modules": list(set(b.moduleName for b in group if b.moduleName)),
                    "severity": "high" if any(b.severity in ("1", "2") for b in group) else "medium",
                    "message": f"同一SN {sn} 存在 {len(group)} 个缺陷，可能为同一根因",
                })
        return correlations
```

```python
    def analyze_version_cluster(self, bugs: list[ZentaoBug]) -> list[dict]:
        """按版本+模块聚簇，发现批次性问题"""
        from collections import defaultdict
        version_module = defaultdict(list)
        for bug in bugs:
            version = bug.openedBuild or "未知版本"
            module = bug.moduleName or "未分类"
            version_module[(version, module)].append(bug)

        correlations = []
        for (version, module), group in version_module.items():
            if len(group) >= 3:  # 同版本+模块 3+ 个 Bug
                correlations.append({
                    "type": "version_cluster",
                    "version": version,
                    "module": module,
                    "bug_count": len(group),
                    "message": f"版本 {version} 的 {module} 模块集中出现 {len(group)} 个缺陷",
                })

```

**3. 时间聚簇 — 突增预警**

```python
    def analyze_time_cluster(self, bugs: list[ZentaoBug],
                              window_days: int = 7) -> list[dict]:
        """按时间窗口聚簇，发现突增"""
        from collections import defaultdict
        from datetime import datetime, timedelta

        daily_count = defaultdict(list)
        for bug in bugs:
            if bug.openedDate:
                day = bug.openedDate[:10]
                daily_count[day].append(bug)

        correlations = []
        days = sorted(daily_count.keys())
        for i in range(len(days)):
            window_bugs = []
            for j in range(i, min(i + window_days, len(days))):
                window_bugs.extend(daily_count[days[j]])
            # 按模块分组
            module_count = defaultdict(list)
            for b in window_bugs:
                m = b.moduleName or "未分类"
                module_count[m].append(b)
            for module, group in module_count.items():
                if len(group) >= 5:
                    correlations.append({
                        "type": "time_cluster",
                        "start_date": days[i],
                        "end_date": days[min(i + window_days - 1, len(days) - 1)],
                        "module": module,
                        "bug_count": len(group),
                        "message": f"{days[i]}~{days[min(i+window_days-1,len(days)-1)]} "
                                   f"{module} 突增 {len(group)} 个缺陷",
                    })
        return correlations
```

## P1-2：智能指派推荐

### 现状问题

当前指派人映射（`_map_assignee`）是静态规则链：
1. 配置映射 → 2. 拼音匹配 → 3. 成员搜索 → 4. 回退创建人

问题：
- 新员工入职后，历史映射无记录
- 跨部门 Bug 需要手动重新指派
- 没有考虑"谁修复最快"的历史数据

### 方案设计

#### 核心思路

基于 TB 已有任务的历史数据，构建"分类 → 执行者 → 修复速度"矩阵：

```
                    执行者A    执行者B    执行者C
IOT-其他问题         3h         8h         -
应用-UI问题          -          2h         6h
算法-路径规划        5h         -          1.5h
```

对新 Bug，根据分类结果 + 矩阵，推荐修复最快的执行者。

#### 实现

```python
class SmartAssigner:
    """智能指派推荐：基于历史修复速度"""

    def __init__(self, teambition: TeambitionClient, config: dict):
        self.teambition = teambition
        self.config = config
        self._assignment_matrix = {}  # {(category, executor_id): avg_hours}
        self._category_executors = {}  # {category: [executor_id, ...]}
        self._user_names = {}          # {executor_id: display_name}

    def learn_from_history(self, tasks: list[TeambitionTask]):
        """从 TB 已关闭任务中学习指派历史"""
        for task in tasks:
            if not task.executorId:
                continue
            category = self._get_category(task)
            if not category:
                continue

            # 计算修复时间
            fix_hours = self._calc_fix_hours(task)
            if fix_hours is None:
                continue

            key = (category, task.executorId)
            if key not in self._assignment_matrix:
                self._assignment_matrix[key] = []
            self._assignment_matrix[key].append(fix_hours)

        # 计算平均修复时间
        for key, hours_list in self._assignment_matrix.items():
            cat, eid = key
            avg = sum(hours_list) / len(hours_list)
            self._assignment_matrix[key] = round(avg, 1)

            if cat not in self._category_executors:
                self._category_executors[cat] = []
            self._category_executors[cat].append((eid, avg))

        # 按修复速度排序
        for cat in self._category_executors:
            self._category_executors[cat].sort(key=lambda x: x[1])

        logger.info("指派矩阵学习完成: %d 个分类 × %d 个执行者",
                     len(self._category_executors),
                     len(set(eid for _, eid in self._assignment_matrix.keys())))

    def recommend(self, category: str, department: str = "") -> Optional[str]:
        """推荐最佳执行者

        Args:
            category: 缺陷分类（如 "IOT-其他问题"）
            department: 部门约束（如 "IOT"，限定本部门人员）
        Returns:
            推荐的 executor_id，无推荐返回 None
        """
        candidates = self._category_executors.get(category, [])
        if not candidates:
            return None

        # 如果有部门约束，过滤非本部门人员
        if department:
            dept_candidates = [
                (eid, h) for eid, h in candidates
                if self._user_dept.get(eid) == department
            ]
            if dept_candidates:
                candidates = dept_candidates

        # 返回修复速度最快的执行者
        return candidates[0][0]  # (executor_id, avg_hours)
```
