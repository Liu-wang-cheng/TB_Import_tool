1克隆仓库到本地

方式一：通过 GitHub 网页复制地址

打开仓库页面，点击绿色的 Code 按钮：

方式二：直接在终端执行

Terminal # 克隆仓库到本地（会在当前目录创建 TB_Import_tool 文件夹）
$ git clone https://github.com/Liu-wang-cheng/TB_Import_tool.git

# 进入项目目录
$ cd TB_Import_tool

# 安装依赖
$ pip install -r requirements.txt
提示：如果还没有安装 Git，去 git-scm.com 下载安装。Windows 用户安装时一路 Next 即可。

2创建自己的分支

不要直接修改 main 分支。每次修改前，创建一个新分支：

Terminal # 先拉取最新代码（养成好习惯，每次开始前都拉一下）
$ git pull origin main

# 创建并切换到新分支
# 分支名建议用 英文描述-你的名字，例如：
$ git checkout -b fix-login-bug-zhangsan
$ git checkout -b add-export-feature-lisi

# 确认当前分支（星号 * 标记的就是当前分支）
$ git branch
* fix-login-bug-zhangsan
  main

3修改代码

用你习惯的编辑器（VS Code、PyCharm、记事本等）修改代码。

注意：配置文件 configs/*.yaml 包含敏感凭证，已在 .gitignore 中排除。
首次使用请复制模板：
cp configs/zentao.yaml.example configs/zentao.yaml，然后填写实际值。

修改完成后，查看改动状态：

Terminal # 查看哪些文件被修改了
$ git status
Changes not staged for commit:
  modified: src/sync_engine.py
  modified: gui/main_window.py

# 查看具体改了什么
$ git diff

4提交并推送

Terminal # 将修改的文件加入暂存区
$ git add src/sync_engine.py gui/main_window.py

# 或者一次添加所有修改的文件（注意不要误添加不需要的文件）
$ git add .

# 提交，附带说明信息
$ git commit -m "fix: 修复同步时标题截断的问题"

# 推送到 GitHub（首次推送新分支需要 -u）
$ git push -u origin fix-login-bug-zhangsan
提交信息规范：
- fix: 修复了什么问题 — 修复 Bug
- feat: 新增了什么功能 — 新功能
- docs: 更新了什么文档 — 文档变更
用中文或英文都可以，关键是说清楚改了什么。

PR 说明怎么写：简单描述改了什么、为什么改、怎么测试的。不用很长，几句话就行。让审核人能快速理解你的改动。

常见问题

别人已经合并了代码，我怎么同步？

Terminal # 先切回 main
$ git checkout main

# 拉取最新代码
$ git pull origin main

# 再创建新分支继续工作
$ git checkout -b your-new-branch

改着改着发现需要从 main 拉最新代码？

Terminal # 在你的分支上，合并 main 的最新代码
$ git fetch origin
$ git merge origin/main

不小心改错了，想放弃修改？

Terminal # 还没 add — 恢复单个文件
$ git checkout -- src/sync_engine.py

# 还没 add — 恢复所有文件
$ git checkout -- .

# 已经 add 了但还没 commit
$ git reset HEAD src/sync_engine.py

不会用命令行，能用工具操作吗？

可以。以下工具都有图形界面，操作更直观：

  • VS Code — 左侧源代码管理面板，点击 + 暂存、写消息、点 ✓ 提交、点 ↑ 推送
  • GitHub Desktop — 专门为 GitHub 设计的桌面客户端，desktop.github.com 下载
  • PyCharm / IDEA — 底部 Git 面板，可视化 diff、commit、push
  • TortoiseGit — 右键菜单集成，Windows 老牌工具
